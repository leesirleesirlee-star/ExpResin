## 方针 · 主动发现「树脂话语体系下的计算机科研问题」

> 导师提醒（2026-09-23）：**在本产品研发过程中，尽量去发现这个领域——树脂话语体系下的计算机相关科研问题。**

即：不做"纯工程交付"。每个功能模块落地时都要反问一次：
*这里有没有一个以树脂/吸附分离实验语言表达的、内核是计算机科学的问题？*

- **机制升级**：由**被动登记**转为**主动发现**。
  - 原机制：工程受阻或数据复盘时才登记（RO-001 ~ RO-005 均为被动触发）。
  - 新机制：每轮工作结束前，主动扫描本轮全部**决策点**（算法阈值、数据结构、数据流、
    人机交接、跨源一致性），把"凭经验定下的规则"转为"可研究的问题"。
- **判别标准**（满足任一即可登记草案）：
  1. 代码里存在**凭经验设定的阈值或启发式**而无理论依据（如穿透点 5% 阈值）；
  2. 存在**多策略可选、而选择依据未量化**的判定（如归属、裁决、单位推断）；
  3. 存在**人肉完成、可自动化**的步骤（如把 Word 模板手工转写成配置）；
  4. 真实数据复盘中出现**系统性偏差或非确定性**（如幻影浓度、跨重复运行跳变）。
- **语言要求**：问题以树脂/吸附分离实验的语言表述（穿透点、平衡时间、标定曲线、qₑ、BV…），
  内核对应可发表的计算机/数据科学问题（表格理解、变点检测、数据溯源、本体对齐、模式发现…）。
- **发现雷达**（话语区 → 问题族 → 已登记）：

  | 树脂/吸附分离话语区 | 典型表述 | 内核问题族 | 已登记 |
  |---|---|---|---|
  | 结构与分块 | 一个 sheet 多块、多级表头、空列分隔、"这块是标定还是样品" | 表格结构识别、切分不确定度 | RO-010 |
  | 标定与反算 | 标定曲线、截距、检出限、"calculated ppm" | 校准可靠性、测量逆问题 | RO-003 / RO-004 |
  | 列与单位 | 无表头列、稀释 N 倍、BV、time/h、meq/g | 列身份与单位推断、量纲推理 | RO-002 / RO-005 / RO-008 / RO-009 |
  | 穿透与平衡 | 穿透点 5%、耗尽 95%、平衡时间、qₑ | 变点检测、首达时间、平台估计 | RO-006 / RO-012 |
  | 记录 vs 复算 | 表内自算值 vs 引擎复算值 | 数据谱系、冲突裁决 | RO-007 |
  | 人机交接 | 逐列确认、低置信度高亮、人工改判 | 人机协同、示例检索、主动学习 | RO-013 |
  | 交付与编排 | 模板填充、结构化输出、模型路由 | 输出可靠性、契约编译、推理预算 | RO-001 / RO-011 |

- **每轮扫描清单**（收尾前执行，约 5 分钟）：
  1. 本轮改动的代码/配置里，有没有**凭经验设定的阈值或启发式**？
  2. 有没有**多策略择一、依据未量化**的判定？
  3. 有没有**人肉反复执行、可自动化**的步骤？
  4. 真实数据有没有出现**系统性偏差或非确定性**（跨运行、跨重复）？
  5. 对照发现雷达：本轮工作落在哪个话语区？该区还缺什么？
  6. 命中任一 → 用**树脂语言**写一句问题，按模板登记草案（不必等方案成熟）。
- **草案登记模板**（完整字段见 PRD `ResearchOpportunity`）：
  `触发类型 / 一句话描述（含实测证据）/ 现有方法 / Gap / 建议方向 / 核心研究问题 / 实验设计 / 目标会议 / 优先级`
- **观察池**（证据尚不足，暂不单列 RO）：
  1. **识别缓存与可复现性的相互作用**：同一文件"命中缓存（确定性回放）"与"重新识别（概率采样）"
     给出不同确定性的结论，直接影响 Benchmark 公平性；`RECOGNITION_RULE_VERSION` 何时应扩展为语义级失效？
     （来源：设计 ChangeLog 第 16 条）
  2. **人工改判的传播**：确认一列后，同表/跨表"同类列"是否应联动改判——主动学习中的传播问题。
     （来源：W8 逐列确认交互）

## RO-001 · 推理型模型的 reasoning 配额与结构化输出可靠性

- **触发类型**：工程阻碍
- **描述**：DeepSeek V4 系列为推理型模型，`reasoning_content` 会占用 `max_tokens` 配额。
  实测在中文长 prompt 的结构化抽取任务中，pro 模型 reasoning 达约 1323 tokens，
  个别调用出现 reasoning 失控并导致 JSON 输出被截断（`finish_reason=length`）。
- **现有方法**：简单提高 `max_tokens`，缺乏系统性依据。
- **Gap**：缺少「任务复杂度 → 模型路由 + 推理预算」的量化方法；
  缺少对 reasoning 长度的事前预测与预算控制。
- **建议方向**：结构化抽取任务的模型路由与 reasoning 预算策略研究。
- **核心研究问题**：给定任务类型与输入长度，如何选择成本最低且能保证 JSON 完整性的
  模型与推理预算？
- **实验设计**：对同一批字段抽取任务，在 {pro, flash} × max_tokens 网格上测量
  reasoning_tokens、JSON 完整率、字段准确率、成本。
- **目标会议**：ACL / EMNLP（LLM 可靠性）
- **优先级**：P1

## RO-002 · 异构实验表格的跨块映射一致性

- **触发类型**：Benchmark 观察
- **描述**：Benchmark v0 显示 27 个列块跨块映射一致性 100%、有效列覆盖率 100%，
  但标定块的 analyte 判定准确率为 84.6% —— 2 处错误均因区块标题（含 SO4 字样）
  污染了本应为 Cl 的列块判定。
- **现有方法**：依赖模型自身判断，缺少针对性的上下文隔离。
- **Gap**：缺少对「标题级上下文污染列级判定」这一失效模式的检测与纠正机制。
- **建议方向**：证据驱动的上下文隔离 —— 列级判定只依据列自身证据（表头/单位/数值范围），
  区块标题仅作为弱提示。
- **实验设计**：构造「标题误导」对抗子集，对比 全局上下文 / 列块隔离 / 隔离+投票
  三种策略下的字段准确率与一致性。
- **目标会议**：ACL / EMNLP（科学表格理解）
- **优先级**：P1

## RO-003 · 标准曲线截距引起的"幻影浓度"与近检出限系统性偏差

- **触发类型**：W7 科学计算引擎复算验证（真实数据）
- **描述**：真实实验表自带的线性标定曲线截距非零，导致**零信号被反算出非零浓度**
  （本文件称"幻影浓度" `c_phantom = -b / k`）。这不是舍入误差，而是会直接污染结论的系统偏差。

  实测两条真实曲线：
  | 标定块 | 拟合方程 | 幻影浓度 | 样本最小非零浓度 |
  |---|---|---|---|
  | `0121#R3-3/B1` | y = 0.292594x − 0.295392 | **1.010 ppm** | 0.000933 ppm |
  | `0305-600#R2-2/B1` | y = 0.263536x − 0.073180 | **0.278 ppm** | 0.045835 ppm |

  **决定性证据**：`0305-600` 样本第 15 行（唯一离群点，相对偏差 604%）表内自算值 0.045835 ppm、
  引擎复算值 0.322825 ppm；而幻影浓度 0.277685 ppm ——
  `0.045835 + 0.277685 = 0.323520 ≈ 0.322825`。
  **即该离群点的偏差几乎完全由截距解释，不存在"数据错误"或"识别错误"。**
  在穿透曲线中，尾端浓度本应趋近于 0，幻影浓度会使尾端始终被读成约 1 ppm，
  从而系统性扭曲穿透点位置与吸附容量（`0121` 的 Ce 即被读成 0.998 ppm 而非 ~0）。
- **现有方法**：仪器软件通常给出带截距的最小二乘拟合，研究者直接沿用；
  未见对"近零区外推有效性"的例行校验。
- **Gap**：缺少「标定曲线在近零区的可用性」判定标准与置信区间；
  缺少「强制过原点 / 带截距 / 加权拟合」对低浓度结论影响的量化对比。
- **建议方向**：分析化学标定曲线的**低浓度端可靠性建模** ——
  过原点约束、加权最小二乘（1/x 或 1/x²）、检出限（LOD/LOQ）与置信带的联动。
- **核心研究问题**：在穿透曲线/等温线实验中，标定曲线近零区的截距偏差如何定量影响
  穿透点、传质区长度与吸附容量？何种拟合约束能最小化该偏差而不牺牲高浓度端准确度？
- **实验设计**：取真实标定与样本数据，对比 {带截距 OLS, 强制过原点, 1/x 加权, 1/x² 加权}
  四种拟合下的 (a) 零信号反算浓度、(b) 尾端浓度轨迹、(c) 穿透点 BV、(d) 吸附容量 q；
  并以标准加入法或独立 ICP 结果作为外部真值锚点。
- **目标会议**：Analytical Chemistry / Talanta / Chemometrics（分析化学计量学）
- **优先级**：P1

## RO-004 · 标定曲线归属的自动推断与置信度量化

- **触发类型**：W7 科学计算引擎复算验证（真实数据）
- **描述**：真实实验表**普遍不显式声明"某样本块使用了哪条标定曲线"**，
  而同一工作表内常并存多条候选曲线（同离子、不同浓度范围）。
  引擎必须自行推断归属，推断错误会带来数十倍量级的系统性错误。

  实测 `0305-600`：候选 `B1`（0–25 ppm）与 `B2`（0–100 ppm）。
  样本信号与 `B1` 一致（中位相对偏差 0.82%），与 `B2` 相差 37%；
  但样本浓度（约 46–52 ppm）**超出 B1 标定范围约 2 倍**（86% 的点需外推），
  即"最一致的那条曲线恰恰不是覆盖该浓度范围的那条"——
  说明仪器实际沿用的是 `B1`，其高浓度端结果本身即为外推值。

  实测 `0121`：**朴素评分（平均相对偏差）会选错**。
  B1 均值 228.5 / B2 均值 164.9 → 选了 B2；而正确答案是 B1（单点偏差 0.44% vs 30%）。
  根因：11 个样本点中 10 个处于检出限附近，相对偏差因分母趋零而爆炸至 780–1082，
  均值被近零点完全支配。改为「剔除近零点 + 中位数」后选中 B1，
  但此时可对照点仅剩 **1 个** —— 归属结论本身极不稳固。
- **现有方法**：无自动归属机制；人工凭经验判断，且判断依据往往未留痕。
- **Gap**：缺少「标定曲线 ↔ 样本块」归属的自动推断方法，
  以及**归属置信度的量化表达**（尤其当可对照点极少、或一致性最优与范围覆盖冲突时）。
- **建议方向**：**证据加权的标定归属推断** ——
  可对照点数量、浓度可比性、标定范围覆盖度、信号数量级一致性、时间/实验批次邻近性
  等多源证据的融合，并输出归属置信度与"需人工确认"信号。
- **核心研究问题**：在缺少显式声明的异构实验表中，如何以可校准的置信度推断
  标定曲线归属，并在证据不足时可靠地"拒答"而非给出高置信的错误归属？
- **实验设计**：构造"归属错误代价"与"证据充足度"二维网格（含近检出限主导、
  范围外推冲突、多批次并存等情形），对比 {朴素均值, 稳健中位数, 范围覆盖优先,
  证据加权融合} 四种策略的归属准确率与"拒答"校准曲线（reliability diagram）。
- **目标会议**：ACL / EMNLP（科学文档理解）或 Journal of Cheminformatics
- **优先级**：P1

## RO-005 · 表头缺失列的确定性身份推断与派生关系识别

- **触发类型**：真实数据复盘（识别快照 + L1 结构证据）
- **描述**：`0305-600#R44-44/B1` 的 **G 列 raw_header 为空**，此前被判为"整列为空的幽灵列"。
  实测证据推翻了这一判断 —— L1 结构层给出：

  | 证据 | 取值 |
  |---|---|
  | `raw_header` | `''`（无表头） |
  | `value_type` | `number` |
  | `fill_ratio` / `non_null` | **1.0 / 22**（整列填满） |
  | `numeric_range` | `[0.0, 2249.76171784]` |
  | 与 E 列（`calculated  ppm`，表内自算）关系 | **严格 G = E × 100**（稀释倍数） |

  逐点验证：E=`8.7451006944` → G=`874.5100694399999`；E=`22.4976171784` → G=`2249.76171784`。

  **即该列是"无表头但有完整数据的派生列"（稀释 100 倍后的原液质量浓度），不是空列。**
  由于缺少表头语义证据，列级映射在 6 次识别中发生**跳变**：
  4 次 → `concentration_mg_l`（conf 0.70/0.72）、2 次 → `None`（conf 0.20）。
  这是**同输入、同模型下的非确定性**，而非真值不同。
- **现有方法**：列身份完全依赖表头语义 + LLM 判断；表头一旦缺失，
  模型只能从数值内容"猜"，且无一致性约束，同一输入重复运行会给出不同结论。
- **Gap**：缺少 ①「表头缺失但数值完整」这类列的确定性判定方法；
  ②「派生列」的自动识别 —— 即列间固定比值/量纲换算关系（ppm ↔ mg/L ↔ mol/L、稀释倍数）
  作为**硬证据**替代缺失的表头语义；③ 非确定性本身的**度量指标**（重复运行一致率）。
- **建议方向**：**数值关系驱动的列身份推断** —— 以列间固定比值、量纲一致性、
  与表内自算列的换算关系为主证据，表头语义降为弱提示；
  证据不足时输出"拒答 + 候选字段建议"，而非在多个结论间随机跳变。
- **核心研究问题**：在表头缺失的异构实验表中，如何仅凭数值内容与列间关系，
  以**可复现**（同输入同输出）的方式确定列身份，并量化身份置信度与拒答阈值？
- **实验设计**：构造"空表头列"子集（真派生列 / 真独立数据列 / 真空列三类），
  对比 {纯 LLM 表头推断, 数值特征规则, 列间关系(比值/量纲)推断, 融合策略} 的
  ① 身份准确率、② **跨重复运行一致性（非确定性度量）**、③ 拒答校准曲线（reliability diagram）。
- **目标会议**：ACL / EMNLP（科学表格理解）或 Journal of Cheminformatics
- **优先级**：P1

## RO-006 · 吸附穿透/耗尽/平衡事件的稳健检测与不确定区间

- **触发类型**：模板派生计算设计（`derive.py` 阈值启发式）+ 真实数据噪声证据
- **描述**：三套实验模板都要求自动派生穿透/耗尽/平衡时间（Column 模板 C 区明确标注
  "Automatically Calculated"）。当前实现用经验阈值：穿透 = 首个 C/C₀ ≥ 0.05；
  耗尽 = 首个 C/C₀ ≥ 0.95；平衡 = |ΔC|/C < 0.05 连续 2 个采样间隔。
  这些阈值没有理论依据，且对三类现实条件脆弱：
  ① **非均匀采样**（早期密、后期疏）——"连续 2 点"在稀疏区会跨越巨大时间跨度；
  ② **近检出限噪声爆炸**（RO-004：相对偏差 780–1082%）——尾端微噪声即可移动耗尽点判定；
  ③ **离群点**（RO-003：604% 偏差点）——单个坏点即可定义穿透点。
- **现有方法**：固定阈值 + 相邻点比较；文献常用穿透点附近线性插值（C/C₀ = 0.05）。
- **Gap**：缺少 ① 对不规则采样与噪声的**稳健事件检测**；② 事件的**不确定区间**（置信带）而非点估计；
  ③ 阈值选择（5%/95%）对最终结论（BV、吸附容量）的**敏感性分析**。
- **建议方向**：变点检测（CUSUM / Bayesian change-point）或高斯过程回归 + 首达时间估计。
- **核心研究问题**：从含噪、非均匀采样的穿透曲线中，如何稳健估计穿透/耗尽/平衡事件时间，
  并给出校准的不确定区间？
- **实验设计**：真实曲线（`0121`、`0305-600`）+ 合成 ground-truth 曲线（不同噪声/采样方案），
  对比 {固定阈值, 线性插值, CUSUM, GP + 首达时间} 的偏差、区间覆盖率、离群点鲁棒性。
- **目标会议**：Chemometrics / Talanta（方法学）或 KDD（时间序列）
- **优先级**：P1

## RO-007 · 记录值与复算值冲突的谱系裁决

- **触发类型**：模板填充浓度口径设计（`data_policy.concentration = engine_first`）+ 缺陷 C 数据价值链复盘
- **描述**：真实实验表里常并存三类同源数值：
  ① 原始响应信号（IC 峰面积/电导）；
  ② **表内自算值**（仪器软件用"它自己的"标定曲线算出，如 `calculated ppm` 列）；
  ③ **引擎复算值**（本系统用识别出的标定曲线重新反算）。
  本次模板填充把口径写死为"引擎复算优先、缺失回退原表值"。但 RO-003/RO-004 已证明
  **引擎复算本身可能系统性错误**（`0305-600` 归属 B1 即外推 2 倍；`0121` 归属结论仅剩 1 个可对照点）；
  而无条件信任记录值同样危险（截距幻影浓度说明仪器软件也带系统偏差）。
  即：**两个来源都不可无条件信任，而当前实现是单向优先级，没有证据化裁决。**
- **现有方法**：单向优先级（记录值优先 / 复算值优先），无冲突检测、无裁决依据留痕。
- **Gap**：缺少 ① 冲突分类学（数值等价 / 单位差 / 外推差 / 归属差 / 幻影差）；
  ② 基于**计算谱系**的冲突裁决方法；③ 裁决置信度与人工升级（拒答）机制。
- **建议方向**：**计算谱系（calculation lineage）驱动的冲突裁决** —— 每个数值连同其产生路径
  （源列、标定曲线、拟合方式、换算链、适用域）一起建模，冲突时按"证据链完整度与适用性"裁决，
  而非按来源身份裁决。
- **核心研究问题**：同一物理量存在多个计算来源时，如何基于谱系证据自动裁决，
  并在证据不足时可靠地升级给人工？
- **实验设计**：以两份真实实验表构造冲突子集（真实存在 + 人工注入），
  对比 {记录优先, 复算优先, 谱系裁决, 谱系裁决+拒答} 的正确率、错误代价、拒答率。
- **目标会议**：VLDB / SIGMOD（数据管理）或 Journal of Cheminformatics
- **优先级**：P1

## RO-008 · 自由文本实验方案 → 可执行数据契约的编译

- **触发类型**：模板配置化（三份老师模板人工转写为 JSON）
- **描述**：老师提供三份**自由文本**实验方案（Batch / Column / Electrochemical），
  每份含 A 信息 / B 数据表 / C 派生量。本次由人工转写为
  `batch|column|electrochemical_template_v1.json`（sections / fields / series / derived、
  单位、from 路径、数据规则）。复盘观察：三份模板结构**高度同构**（A/B/C 三段、列头语义可对齐），
  但**命名与单位不一致**——"Concentration (mg/L)" vs "Effluent Concentration (mg/L)" vs 同名前两者；
  时间单位 min vs s；"Adsorbent mass" vs "Bed volume (BV)"。
  人工转写需逐字比对，成本高、易漏字段、版本难维护。
- **现有方法**：人工读模板 → 手写配置；无一致性校验、无版本追踪。
- **Gap**：缺少 ① 自然语言实验方案 → 可执行模板 schema 的**自动编译**；
  ② 跨模板**槽位对齐**（同物理量不同命名的归一化，与 RO-005 的列级身份推断属不同层级）；
  ③ 编译产物的**语义等价校验**（新模板 vs 参考模板）。
- **建议方向**：以"**实验数据契约**（data contract）"为中间表示的编译管线：
  LLM 抽取候选槽位 + 槽位本体（物理量 × 单位 × 角色：时间/浓度/pH/电位/电流）对齐 +
  合成数据回放等价性测试。
- **核心研究问题**：如何把自由文本实验方案编译为可执行、可验证、可跨方案对齐的数据契约？
- **实验设计**：以三份真实模板 + 扩展模板（不同课题组风格）为基准，
  测量槽位召回/对齐准确率、单位推断准确率、等价性检测的漏报/误报。
- **目标会议**：ACL / EMNLP（信息抽取）或 Journal of Cheminformatics
- **优先级**：P2（当前以人工配置满足交付）

## RO-009 · 离子价态感知的当量换算与量纲校验

- **触发类型**：模板填充的跨模板单位换算实现（`template_fill.py`）
- **描述**：树脂/离子交换领域同时使用**质量浓度**（mg/L、ppm）、**摩尔浓度**（mmol/L）、
  **当量浓度**（meq/L）与**容量单位**（mg/g、mmol/g、meq/g）。
  换算依赖**离子价态与摩尔质量**：SO₄²⁻ 当量 = 96.06/2 = 48.03 g/eq、Cl⁻ = 35.45、Na⁺ = 23.0；
  且当量容量（meq/g）与质量容量（mg/g）**不能直接互相比较**。
  实测：仓库真实数据浓度以 ppm 记录（依赖稀水溶液 ≈ mg/L 假设），而工程指标常用 meq/g
  （如 D201 交换容量 3.7 meq/g）——跨表聚合时若不显式建模价态与基准，数值不可比。
  当前实现：`template_fill` 仅做时间单位换算（h/min/s→s），浓度按 ppm ≈ mg/L 假设；
  单位识别失败时降级为"按原值处理 + 提示人工核对"。
- **现有方法**：人工换算法；工具层只做数值缩放，不携带化学假设。
- **Gap**：缺少 ① 从列头文本 + 数值分布**推断列单位**（unit inference）的可靠方法；
  ② **价态/量纲一致性校验**（跨列、跨表、与容量指标的一致性）；
  ③ 换算链中**化学假设的显式携带与拒绝机制**（无法安全换算时拒绝而非静默降级）。
- **建议方向**：**离子本体感知的量纲层** —— 以离子本体（价态、摩尔质量、当量）为约束，
  把单位换算建模为受限推理问题，假设必须显式声明并进入导出 provenance。
- **核心研究问题**：在树脂领域异构单位体系下，如何自动推断列单位、检测不可换算组合，
  并让每一次换算的化学假设可追溯、可拒绝？
- **实验设计**：构造单位混淆子集（ppm/mg/L/meq/L/mmol/L 混排、缺单位表头、当量容量 vs 质量容量），
  对比 {人工规则, 单位本体推理, 推理+拒绝} 的换算准确率与"危险换算"拦截率。
- **目标会议**：Journal of Cheminformatics / Chemometrics
- **优先级**：P2

## RO-010 · 多块异构实验表的确定性结构切分与块类型判定

- **触发类型**：主动扫描（L1 结构解析启发式复盘）+ Benchmark v0 / 真实数据观察
- **描述**：真实实验簿（如 `20250528 DHT Cl SO4.xlsx`：7 sheet / **27 个数据列块**）中，
  同一个 Sheet 内并存标定块、样品块、容量块与曲线块。L1 用一组**无理论依据的启发式**完成切分：
  表头行 = "文本单元格 ≥ 2 且文本数 ≥ 数值数，且下一行非空"；数据区结束 = **连续 3 空行**
  （`blank_tolerance=3`）；列块 = 以"表头与数据均空"的列分隔；块类型 = 关键词匹配
  （`bv`→样品 / `capacity`→容量 / `time+ph`→pH 曲线 / `area+ppm`→标定）；标题 = 表头块上方最近非空文本。

  实测脆弱性：
  ① 空行既是"块间分隔"又可能是数据区内部的合法空行——容差 3 既是经验值也未做敏感性分析，
  真实表里"稀疏子表 + 注释行"会让同一块被切碎或相邻块被合并；
  ② `-003` 的表单声明为 batch，但数据表含 `bed_volume (BV)` 与 `time/h` 列（09-23 数据观察 4.1）——
  关键词块类型与声明实验类型会相互矛盾，当前无一致性校验；
  ③ 下游 `canonical._locate` 依赖"识别快照与重解析的块 ID 完全一致"：块 ID 由行号/序号生成，
  解析器一旦升级，历史快照将无法再对齐——标定块尚会写 note，**样本块则是静默产出空行**。
- **现有方法**：通用表格结构识别（TableSense 等 TSR/表格检测工作）多面向 Web/PDF 与"单表"假设；
  对"多块混排 + 多级表头 + 自由文本注释"的科研工作表覆盖不足，且少有方法对切分结果显式给出不确定度。
- **Gap**：缺少 ① 块边界（数据区/列块）的稳健判定与**参数敏感性分析**；
  ② 块类型判定与声明实验类型的**一致性校验**；③ 结构身份的可版本化编码与**跨版本再对齐**。
- **建议方向**：把 L1 从"规则脚本"升级为**带不确定度的结构切分器**：
  多信号融合（空行/填充密度/表头特征/列名语义）+ 边界置信度 + 内容指纹式稳定 ID（替代行号 ID）。
- **核心研究问题**：在混有自由文本、多级表头与稀疏子块的真实科研工作表中，
  如何以**确定且带置信度**的方式切分数据块、判定块类型，并让结构身份在解析器版本演进后仍可再对齐？
- **实验设计**：以现有 7 sheet / 27 块为种子，扩展 20–50 张含块级标注的实验表；
  对比 {现行启发式, 参数网格, 多信号融合 + 置信度} 的块边界 F1、块类型准确率、跨版本 ID 再对齐率；
  报告 `blank_tolerance` 等参数的敏感性曲线。
- **目标会议**：ACL / EMNLP（科学文档理解）或 ICDAR / DAS（文档分析）
- **优先级**：P1

## RO-011 · Trace as State 的条件增益与自适应推理预算

- **触发类型**：主动扫描（PRD 方法主张 vs 实现事实的差异）
- **描述**：PRD §4.2 将 Trace as State 两轮推理列为推理增强核心（援引 GraphWalks Parents
  精确匹配 29.2% → 81.8%），但工程实现**默认关闭**：`map_block(use_trace=False)`，
  注释理由是"V4 自带 reasoning，已具备先思考再回答的能力，单轮即可保证质量，同时避免长 prompt 下推理链失控"。
  **两轮推理在 ExpResin 自身任务上的增益，从未被测量**；而其成本是实打实的：
  pro 单轮 reasoning 已达约 1323 tokens（实测），`4096` 上限会周期性触发"截断→翻倍重试"
  （单块耗时 ~45s → 93s），两轮再翻倍。
- **现有方法**：CoT / "先笔记后回答"的收益研究多在通用推理与长文档 QA；
  对"结构化表格抽取 + 自带推理链的模型"这一组合，缺少增益条件与净收益的实证。
- **Gap**：① 缺少 {单轮原生推理, 显式两轮, 笔记压缩两轮, 选择性两轮} 在同任务同数据上的对照；
  ② 缺少"是否值得花第二轮"的**事前预测**（块级特征 → 增益概率）；
  ③ 缺少把 reasoning/笔记 token 计入后的**净收益**判定标准。
- **建议方向**：**条件化推理预算**——把"是否补第二轮"建模为决策问题：
  以块级特征（列数、单位混乱度、缺表头比例、数值范围冲突…）预测增益，仅在预期净收益为正时触发。
- **核心研究问题**：在自带推理链的 LLM 上做科学表格结构化抽取，显式两轮推理在什么条件下仍有增益？
  能否以块级特征事前预测该增益，并据此分配推理预算？
- **实验设计**：以 Benchmark（27 块种子，可扩展）为固定集，在 {V4-Flash, V4-Pro} × {单轮, 两轮, 选择性两轮}
  网格上测字段准确率、跨重复一致性、token 成本与时延；交叉验证训练增益预测器；
  按 PRD §4.2.4 记录"回退单轮"的条件与证据。
- **目标会议**：ACL / EMNLP（LLM 效率与可靠性）
- **优先级**：P2

## RO-012 · 平衡浓度（Ce）的平台估计与 q 的不确定度传播

- **触发类型**：主动扫描（真实数据复算证据链 RO-003/004 + 派生计算实现复盘）
- **描述**：容量 q = (C₀ − Ce)·V/m 直接依赖 Ce，而真实表通常**不显式给出 Ce**：
  `derive_batch` 取"最后一个有效浓度点"（method=`last valid concentration point`）；
  `canonical._build_samples` 反向取"最后一个正浓度"（`last_sample_as_equilibrium` / `last_sample_computed`）。
  该口径在三种情形下直接扭曲 q：① 尾端尚未真正平台（动力学未平衡）；
  ② 尾端落入近检出限噪声区（`0121` 的 Ce 被读成 0.998 ppm 而非 ~0，见 RO-003）；
  ③ 尾端点超出标定范围（已标注 `equilibrium_extrapolated` 风险，但只提示、不换算）。
  RO-006 解决的是平衡**时间**的判定，未覆盖平衡**浓度**的估计与误差传播——两者是不同统计对象。
- **现有方法**：吸附文献常用"平衡后取平均"或直接取末点；统计上对应平台/渐近线估计
  （渐近回归、变点后均值、GP），但实验软件与表格流程极少实现，更少把 Ce 的不确定度传入 q。
- **Gap**：① 缺少从有限、含噪、非均匀采样序列估计平台值 Ce 的稳健方法；
  ② 缺少 Ce 不确定度 → q、去除率、"是否已达平衡"的**传播链条**；
  ③ 缺少"末点法 vs 平台法"对最终结论影响的量化与适用边界。
- **建议方向**：把 q 从"点估计"升级为**区间估计**：平台检测（变点 + 渐近回归/GP）→ Ce 置信区间 →
  蒙特卡洛/解析传播 → q 与去除率区间 + "平衡是否稳健达成"的判定。
- **核心研究问题**：在含噪且可能尚未平台的吸附动力学数据中，如何稳健估计平衡浓度并给出置信区间，
  该区间如何定量影响吸附容量与去除率结论？
- **实验设计**：真实序列（`0121`、`0305-600`、`RES-20260921-003`）+ 合成序列（已知平台真值，
  扫描噪声/采样/未平衡程度），对比 {末点法, 平台均值法, 渐近回归, 变点+均值, GP} 的
  Ce 偏差、q 区间覆盖率；产出"末点法不可用"的判据。
- **目标会议**：Chemometrics / Talanta（吸附实验方法学）
- **优先级**：P1

## RO-013 · 人工改判的检索化复用：无微调条件下的人机协同映射（草案）

- **触发类型**：主动扫描（宪法约束"人工确认不是重训" + FR-05 设计决策）
- **描述**：逐列确认会持续产生**人工改判**（W8 实测：无表头列同输入 4:2 跳变，
  人工改判是唯一确定性出口）。宪法规定确认数据不用于微调，只能进 Few-shot 示例库（FR-05：
  确认结果写入 MappingExample，动态检索最相似 3–5 条作 Few-shot）。
  但目前改判只被**存储**、尚未回到识别链路（`mapping.py` 的 prompt 里只有一个固定示例，无检索）——
  **累积的专家知识目前不影响后续映射质量**；示例选择策略（何为相似、取几条、如何排序、
  陈旧/冲突示例如何退役）亦无依据。
- **现有方法**：ICL 示例选择研究（kNN 检索、多样性选择、难度感知）多在通用 NLP 任务；
  对"专家逐列改判 → 领域表格映射"的在线场景，缺少选择策略与漂移治理的实证。
- **Gap**：① 缺少"改判 → 示例"的表示与检索方法（两个列块"相似"的定义）；
  ② 缺少示例库的增长治理（冲突、过时、偏置）；③ 缺少收益度量（相对无示例基线的准确率与修正次数）。
- **建议方向**：**改判驱动的检索增强映射**——把每次确认编码为（语境指纹，纠正后映射），
  检索 3–5 条入 prompt；配套示例冲突检测与退役策略，保证"随确认累积单调改善"。
- **核心研究问题**：在允许人工改判但不允许微调的约束下，如何把持续的专家确认转化为可检索示例，
  使后续映射准确率提升、人工修正次数下降，且该改善可度量、可回溯？
- **实验设计**：以 Benchmark 为评测集，模拟"逐日累积改判"的在线设定，对比
  {无示例, 随机示例, kNN 相似检索, 多样性+冲突治理} 的 top-1 准确率、低置信度覆盖率、平均修正次数；
  绘制示例库增长的边际收益曲线。
- **目标会议**：ACL / EMNLP（人机协同 / In-context Learning）
- **优先级**：P2（依赖确认闭环接入识别链路后实施）
